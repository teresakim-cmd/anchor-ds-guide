Section 01

우리의 핵심 원칙 3가지

디자인 시스템의 무결성을 지키는 세 가지 핵심 원칙. 이 약속만 지키면 디자인과 코드가 어긋나지 않습니다.

No Atomic

원자 단위로 조합해 새 UI를 만들지 않습니다. 정의된 '기능적 컴포넌트' 유닛을 사용합니다.

Semantic Only

Hex 코드를 직접 입력하지 않습니다. 맥락이 담긴 시멘틱 토큰($BgPrimary 등)만 사용합니다.

Edit Lock

Variable 수정은 공통 참여 디자이너(시스템 운영 권한 보유 멤버)만 가능합니다. 변경이 필요하면 운영팀에 요청해 주세요.

02‑2. Figma & Dev Workflow

PascalCase Naming

모든 토큰과 베리언트 명칭은 첫 글자를 대문자로 시작하는 파스칼 케이스를 준수합니다. ButtonPrimary, BgPrimary

Pre‑Sync before Change

토큰이나 컬렉션명을 변경할 계획이 있다면 반드시 개발팀에 사전에 내용을 공유해야 합니다.

Marking & Dev Check

작업 완료 파트에는 ✅ 표시를 추가하고, Figma의 Dev Check 기능을 활성화하여 안내합니다.

01 크기 조정 Size 속성으로 변경

컴포넌트의 Size 속성을 변경해 사용합니다. 각 버튼 타입마다 정의된 사이즈를 사용할 수 있습니다.

정의되지 않은 사이즈는 사용하지 않으며, 버튼은 일괄로 조정해 사용합니다.

02 컬러 변경 Color 속성으로 변경

컴포넌트의 Color 속성을 변경해 사용합니다. 각 버튼 타입마다 정의된 컬러를 사용할 수 있습니다.

정의되지 않은 컬러는 사용하지 않으며, 임의로 조정해 사용하지 않습니다.

03 상태값 State 속성 · Active / Inactive / Hover / Loading

컴포넌트의 State 속성을 변경해 사용합니다. 버튼의 경우 공통적으로 Active · Inactive · Hover · Loading 값을 사용할 수 있습니다.

상태값을 임의로 변경해 사용하지 않습니다.

04 비활성화 전환 Disabled · Boolean Toggle

켜기 / 끄기처럼 비활성화(Disabled) 상태를 Boolean (Toggle)로 제어합니다.

05 아이콘 — 사용 · 변경 · 찾기 Icon 속성 활용

5‑1. 사용 — Boolean Toggle

아이콘의 사용 여부를 Boolean (Toggle) 값으로 변경합니다. 사용처에 따라 모양된 버튼 타입을 사용할 수 있습니다.

5‑2. 변경 — Icon 속성에서 선택

시스템에 정의된 아이콘은 변경이 가능합니다. 컴포넌트의 Icon 속성에서 원하는 아이콘을 선택해 사용할 수 있습니다.

!Blank의 경우 시스템 정의를 위한 더미 아이콘으로, 실 서비스에서 사용하지 않습니다.

5‑3. 찾기 — 키워드 검색

시스템에 정의된 아이콘은 키워드 검색이 가능합니다. 사용하고 싶은 아이콘의 정확한 이름을 알기 어렵다면, 키워드로 검색해 원하는 아이콘을 찾아 사용하세요.

컴포넌트별 사용법 — Icon 기본 사용 / 변경 / 찾기 / 컬러

Icon/Icons는 가장 자주 쓰는 베이스 컴포넌트. 컬러는 유연하게 변경되지만 형상은 시스템 정의대로 사용합니다.

01 기본 컴포넌트 사용 Icon / Icons를 베이스로 사용

Icon / Icons를 기본 베이스 컴포넌트로 사용합니다.

  • 각 정의된 아이콘의 형상을 해치지 않기 위함
  • 컬러값이 유연하게 변경 가능 (Variant 컬러 토큰만 사용)
  • 네비게이션·탭 등 상위 컨테이너 안에서도 Icon 인스턴스 그대로 배치
02 변경 Icon 속성에서 원하는 아이콘 선택

시스템에 정의된 아이콘은 변경이 가능합니다. 컴포넌트의 Icon 속성에서 원하는 아이콘을 선택해 사용합니다.

!Blank의 경우 시스템 정의를 위한 더미 아이콘으로, 실 서비스에서 사용하지 않습니다.

03 찾기 키워드 검색

시스템에 정의된 아이콘은 키워드 검색이 가능합니다. 정확한 이름을 알기 어려울 때 키워드로 빠르게 찾으세요.

04 컬러 변경 Primary 사용 X · 기본 Secondary

아이콘은 Primary (Black1000)를 사용하지 않습니다.

  • 기본 컬러: Secondary (Black900)
  • 아이콘의 형상을 변경해도 컬러값이 유지됩니다.

04‑3. Do & Don't

실무에서 가장 자주 마주치는 6가지 케이스 — 좌우 비교로 빠르게 익혀요.

01

Button — 컴포넌트 인스턴스

실제 Anchor Button 스펙: h36 · r8 · p0 12 · 15/700
Do

시멘틱 토큰이 매핑된 Primary 인스턴스를 그대로 배치합니다. $BackgroundInteractionPrimary · $TextStaticWhitePrimary

Don't

임의 #7F5AF0 컬러 · 13px 23px 비규격 패딩 · radius 5 오프그리드 — 다크모드·디바이스 변환에서 모두 깨집니다.

02

Color — 시멘틱 토큰만

다크 모드 자동 전환을 보장하는 단 한 가지 길
Do
$BackgroundInteractionPrimary $TextStaticWhitePrimary

맥락이 담긴 시멘틱 토큰만 사용합니다. 토큰 이름 하나로 라이트·다크 모드에 자동 대응됩니다.

Don't
#1E84FF #FFFFFF

Hex 직접 입력은 라이트·다크 분기에 대응하지 못하고, 토큰 이름이 바뀌어도 자동 추적되지 않습니다.

03

Spacing — 4의 배수 그리드

8 · 12 · 16 · 24 · 32 스케일만
Do
8 12 16 24 32

정의된 스페이싱 토큰($Space2 ~ $Space8)만 사용해 컴포넌트끼리 정렬이 어긋나지 않게 합니다.

Don't
13 17 25 31

13px, 17px 같은 임의값은 그리드를 깨고, 코드로 옮겼을 때 매직 넘버가 됩니다.

04

Typography — 정의된 텍스트 스타일

Title / Body / Caption 토큰 사용
Do
$TextTitleL 디자인은 약속이다
$TextBodyM 정의된 스타일만 사용합니다.

텍스트 스타일은 토큰으로만 적용합니다. 사이즈·굵기·행간이 한 묶음으로 동기화됩니다.

Don't
font-size: 23.5px 디자인은 약속이다
font-size: 16.5px 정의된 스타일만 사용합니다.

피그마 텍스트 패널에서 사이즈·행간을 손으로 만지지 않습니다. 코드에는 매핑되는 토큰이 없어 그대로 들어가지 않습니다.

05

Component — 인스턴스 그대로

Detach 금지 · 원자 단위 재조립 금지
Do
INSTANCE Button

정의된 컴포넌트의 인스턴스 1개를 그대로 배치합니다. Variant·Property로만 조정하세요.

Don't
Rectangle + Text + Icon

컴포넌트를 Detach하고 사각형·텍스트·아이콘으로 재조립하면 토큰 추적이 끊어집니다.

06

Scope — 단위 기능 + 여백까지가 한 컴포넌트

그 이상은 Pattern (System Hierarchy 3단계)
Do
Title / TopTitle · Component
타이틀

컴포넌트는 여백을 포함한 최소 단위 기능으로 정의합니다. 예: Title — 타이틀 텍스트 + 외부 패딩까지가 한 묶음.

Don't
"Component"? ← 실은 Pattern
Title Content CTA Button

Title + Content + CTA를 한 덩어리로 묶어 "Component"로 등록하면 안 됩니다 — 그건 Pattern입니다. 패턴을 컴포넌트로 잠가두면 재사용·변형 모두 불가능해집니다.
